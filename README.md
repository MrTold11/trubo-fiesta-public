# trubo-fiesta

## Целевой стек

| Компонент        | Версия                          |
|------------------|---------------------------------|
| ОС (деплой)      | Ubuntu Server 22.04             |
| JRE/JDK          | Java 11                         |
| Spring Boot      | 2.6.3                           |
| СУБД             | PostgreSQL 16 (допустимо до 18) |
| Документация API | springdoc-openapi-ui 1.7.0      |
| Оркестрация      | docker-compose 1.29.2           |

## Локальная разработка (без Docker)

- Swagger UI — http://localhost:8080/swagger-ui.html
- OpenAPI JSON — http://localhost:8080/v3/api-docs
- Health — http://localhost:8080/actuator/health

## Развёртывание

```bash
cp .env.example .env
docker-compose up -d --build
docker-compose logs -f app
```

Поднимаются два сервиса: `app` и `postgres`. Данные БД и файловое хранилище живут
в именованных томах `postgres-data` и `app-storage`.

## Что делает сервис

Загружаете GeoJSON с существующей тепловой сетью, камерами, пространственными
ограничениями и точками подключения. Сервис строит новую сеть до всех точек, выбирает
места присоединения к существующей сети, подбирает условные диаметры, проверяет
предельную длину, считает стоимость и выдаёт до трёх ранжированных вариантов. Результат
выгружается одним GeoJSON в формате раздела 7 технического приложения от 19.09.2026.

Как работает алгоритм и где границы его применения — [docs/algorithm.md](docs/algorithm.md).
Архитектура и принятые решения — [docs/architecture.md](docs/architecture.md).

Адреса после запуска:

| Что | Где |
|---|---|
| Swagger UI | http://localhost:8080/swagger-ui.html |
| Состояние | http://localhost:8080/actuator/health |
| Интерфейс (отдельный контейнер, необязателен) | http://localhost:8081/ |

Сервис — чистый API: вход GeoJSON, выход GeoJSON. Интерфейс вынесен в отдельный
контейнер `ui` на nginx и на работу сервиса не влияет; его можно не запускать.

Справочные таблицы технического приложения лежат в `src/main/resources/rules.yaml`.
Ни одно из этих чисел не зашито в код. Файл можно подменить снаружи переменной
`APP_RULES_FILE` и перечитать без перезапуска через `GET /api/reference/reload`.

Все спорные трактовки правил вынесены в параметры расчёта и переключаются на вкладке
«Параметры»: сервис умеет считать в обеих трактовках, а не в одной выбранной.

Три варианта выдачи — три лучших по показателю содержательно разных дерева подключения:
они различаются местами присоединения к существующей сети и тем, какие точки питаются
от какого присоединения. Алгоритм и доводка геометрии у всех вариантов одни: трасса вдоль
застройки отводами 45° и 90°, выход из зданий по нормали к ближайшей стене, камеры на линии
ствола напротив вводов. Срезка под произвольным углом (приложение допускает любой угол до
90° без удорожания) делается только там, где она убирает заглушку или зигзаг, либо экономит
не меньше порога (по умолчанию 3 млн руб. с учётом длины). Номер варианта совпадает с
рангом по показателю раздела 6, в объяснении каждого варианта написано, чем он отличается
от первого. Переключатель «Только отводы 45° и 90°» запрещает нестандартные углы вовсе.
Углы поворотов и угол в начальном узле пишутся в выгрузку дополнительными свойствами
`turn_angles` и `node_angle` и видны в панели «Объект».

## Решения, которые стоит знать

**Порядок старта.** Формат compose-файла — 3.8, максимум, который понимает
docker-compose 1.29.2. В его схеме `depends_on` — только список строк, длинная форма
с `condition: service_healthy` не поддерживается. Поэтому ожидание БД обеспечивается
иначе: `spring.flyway.connect-retries=60`, `hikari.initialization-fail-timeout=-1`,
healthcheck'и и `restart: unless-stopped`. По той же причине не используется
`deploy.resources` (в 1.29.2 он игнорируется вне swarm) — лимит памяти JVM задаётся
через `JAVA_OPTS=-XX:MaxRAMPercentage=80`.

**Загрузка 3 ГБ без буферизации в heap.** `spring.servlet.multipart.file-size-threshold=0`
заставляет Tomcat писать каждую часть сразу на диск в `spring.servlet.multipart.location`,
минуя память. `server.tomcat.max-swallow-size=-1` и `max-http-form-post-size=-1` снимают
ограничения, которые иначе обрежут такой запрос.

`app.storage.tmp-dir` и `app.storage.root-dir` должны лежать на одной файловой системе:
завершение загрузки — это `Files.move`, то есть переименование внутри одной ФС и полное
копирование 3 ГБ между разными. В образе обе директории находятся внутри одного тома
`/var/lib/trubo-fiesta`.

Диск под `tmp-dir` нужно считать как `одновременные загрузки x 3 ГБ`.

**Секция `app.storage` пока ни к чему не привязана** — это заготовка настроек под будущую
реализацию. При появлении сервиса хранения её нужно связать с `@ConfigurationProperties`.

**Нагрузка на 50 пользователей.** `server.tomcat.threads.max=100`, `max-connections=200`,
пул Hikari на 20 соединений при `max_connections=100` у PostgreSQL. Передача файлов
упирается в I/O, поэтому потоков больше, чем ядер.

**Обратный прокси.** Если перед сервисом появится nginx, ему нужен
`client_max_body_size 3g;` и увеличенные `proxy_read_timeout`/`proxy_send_timeout` —
иначе 3 ГБ не дойдут независимо от настроек приложения.

## Структура

```
Dockerfile                  multi-stage: maven:3.9-eclipse-temurin-11 -> eclipse-temurin:11-jre-jammy
docker-compose.yml          app + postgres
.env.example                шаблон переменных окружения
docs/                       архитектура, описание алгоритма, карта набора данных
ui/                         отдельный контейнер с интерфейсом: nginx, статика без сборки
src/main/resources/
  rules.yaml                справочники технического приложения
  db/migration/             схема базы, Flyway
src/main/java/ru/chmod777/trubofiesta/
  geo/                      проекция EPSG:4326 в EPSG:32637 и геометрические утилиты
  rules/                    загрузка rules.yaml, подбор диаметров, стоимости, формулы
  settings/                 параметры расчёта и их схема для интерфейса
  model/                    сущности кейса и диагностика
  ingest/                   потоковое чтение GeoJSON и сборка доменной модели
  topology/                 существующая сеть в граф, кандидаты присоединения
  routing/                  препятствия, сетка в осях застройки, лучи выхода, поиск пути
  plan/                     дерево подключения
  calc/                     расходы, диаметры, узлы, камеры, присоединения, стоимость
  export/                   выгрузка GeoJSON и встроенная проверка результата
  jobs/                     хранилище файлов, загрузка, очередь расчётов
  db/                       репозитории на JdbcTemplate
  web/                      REST-контроллеры
```

## Тесты

```bash
docker run --rm -v "$PWD":/app -v "$HOME/.m2":/root/.m2 -w /app maven:3.9-eclipse-temurin-11 mvn -B test
```

Проверяются формулы разделов 3 и 6, подбор диаметров по расходу и предельной длине,
неубывание Ду к месту присоединения, специальный проход, обязательные null в выгрузке,
уникальность идентификаторов, повторяемость результата и полный расчёт на синтетическом
наборе. Если рядом лежит `data/dataset.geojson`, дополнительно прогоняется конкурсный набор.

Результат дополнительно проверяется скриптом, который не делит с сервисом ни кода, ни
данных, — `проверка/validate.py` (вне репозитория, только стандартная библиотека Python):

```bash
python3 ../проверка/validate.py data/dataset.geojson выгрузка.geojson
```
